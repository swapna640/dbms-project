## SQL Queries

The SQL component performs analytical queries on the Pizza Sales Management database. The database consists of four related tables: `pizza_types`, `pizzas`, `orders`, and `order_details`. The schema represents pizza types, size-specific pizza variants, order headers, and individual order line items.
The queries are divided into basic, intermediate, and advanced analytical operations.

### Basic Queries

1. **Total Number of Orders**
   Calculates the total number of unique orders placed.

2. **Total Revenue**
   Calculates the total revenue generated from pizza sales using pizza price and ordered quantity.

3. **Highest-Priced Pizza**
   Identifies the pizza variant with the highest price.

4. **Most Common Pizza Size**
   Determines which pizza size has the highest total quantity ordered.

5. **Top 5 Most Ordered Pizza Types**
   Retrieves the five pizza types with the highest ordered quantities.

### Intermediate Queries

6. **Quantity by Pizza Category**
   Uses table joins and grouping to determine the total quantity ordered for each pizza category.

7. **Orders by Hour**
   Groups orders according to the hour of the day to analyze ordering patterns.

8. **Average Order Value**
   Calculates the average revenue generated per order.

9. **Average Pizzas Ordered per Day**
   Groups order quantities by date and calculates the average number of pizzas ordered per day.

10. **Top 3 Pizza Types by Revenue**
    Determines the three pizza types generating the highest revenue.

### Advanced Queries

11. **Revenue Percentage Contribution**
    Calculates the revenue generated by each pizza type and its percentage contribution to total revenue.

12. **Cumulative Revenue Over Time**
    Groups revenue by date and uses a window function to calculate cumulative revenue over time.

13. **Top 3 Pizza Types by Revenue per Category**
    Uses Common Table Expressions (CTEs) and the `RANK()` window function to identify the top three pizza types by revenue within each category.

### SQL Concepts Used

* `SELECT`, `WHERE`, `GROUP BY`, and `ORDER BY`
* Aggregate functions such as `COUNT()`, `SUM()`, and `AVG()`
* `JOIN` and `LEFT JOIN`
* Subqueries
* Common Table Expressions (CTEs)
* Window functions
* `RANK()`
* Revenue and quantity-based aggregation
* Date and time-based analysis

## PL/SQL Queries

The PL/SQL component provides an Oracle PL/SQL implementation of the analytical requirements through a package named `pizza_analytics_full`.

The package contains **5 basic procedures, 5 intermediate operations, and 3 advanced procedures**, along with a `run_all` procedure for executing the printable analyses together.

### Basic Operations

| Procedure                 | Description                                      |
| ------------------------- | ------------------------------------------------ |
| `b1_total_orders`         | Calculates the total number of orders.           |
| `b2_total_revenue`        | Calculates total revenue from pizza sales.       |
| `b3_highest_priced_pizza` | Finds the highest-priced pizza using a cursor.   |
| `b4_most_common_size`     | Determines the most commonly ordered pizza size. |
| `b5_top5_pizza_types`     | Displays the five most ordered pizza types.      |

These procedures demonstrate aggregate queries, joins, cursors, conditional handling, and `DBMS_OUTPUT`.

### Running the PL/SQL Package

Enable `DBMS_OUTPUT` before executing the package:

```sql
SET SERVEROUTPUT ON;
```

To execute all printable procedures:

```sql
BEGIN
    pizza_analytics_full.run_all;
END;
/
```

Individual procedures can also be executed separately:

```sql
BEGIN
    pizza_analytics_full.i5_top3_by_revenue;
END;
/
```

The average pizzas ordered per day is implemented as a function and can be queried using:

```sql
SELECT pizza_analytics_full.i4_avg_pizzas_per_day
FROM dual;
```

The advanced category-wise ranking procedure returns a `SYS_REFCURSOR`:

```sql
VAR rc REFCURSOR;

EXEC pizza_analytics_full.a3_top3_by_revenue_per_category(:rc);

PRINT rc;
```

Query optimisation

### Techniques applied

| # | Fundamental | What it means here |
|---|---|---|
| 1 | **Push aggregation before joins** | `order_details` is large but has only ~96 distinct `pizza_id`s. Aggregate it first, then join the small result to `pizzas` and `pizza_types`. |
| 2 | **Use the right join type** | `LEFT JOIN` restricts join reordering. Every query needs matching rows only, so `INNER JOIN` is used. |
| 3 | **Avoid redundant scans and derived tables** | Window functions and single-pass formulas replace second scans and temporary tables (Q8, Q9, Q11). |
| 4 | **Support the plan with indexes** | Covering indexes let the aggregates run from the index alone. |
| 5 | **Cheaper primitives** | `COUNT(*)` instead of `COUNT(DISTINCT pk)`, and `ROWS` frames instead of the default `RANGE` frame in window functions. |

## Relational Algebra  and Relational Calculus

Each query is expressed in **extended relational algebra (RA)** and **tuple relational calculus (TRC)**. Because optimisation changes only the physical plan, the algebra is the same for the original and optimised SQL. Q5 and Q6 use the corrected logic.

### Notation

| Symbol | Meaning |
|---|---|
| σ | Selection |
| π | Projection |
| ⋈ | Natural join |
| × | Cross product |
| − | Set difference |
| ρ | Rename |
| `G γ F` | Group by `G`, apply aggregate `F` |
| τ | Sort |
| λₙ | Keep first *n* tuples |
| ω | Window operator |
| `AGG{ expr \| cond }` | TRC aggregate extension (aggregate `expr` over tuples satisfying `cond`) |

### Coverage

| Q | RA idea | TRC idea |
|---|---|---|
| 1, 2, 6, 7 | Grouping and aggregation (`γ`) over joins | Aggregate set `AGG{ … }` |
| 3 | Set difference against a self-join (pure RA) | `¬∃q (q.price > p.price)` (pure TRC) |
| 4, 5, 10 | `γ` then `τ`/`λ`, or self-join to find maxima | Count of tuples with a larger value < *n* |
| 8, 9 | Two-level aggregation (`γ` over `γ`) | Nested aggregate over a derived set |
| 11 | Cross product with a one-tuple grand total | Inline `SUM{ … }` in the expression |
| 12 | Self-join with `≤` plus `γ` (the algebraic form of a running total) | Aggregate with `d2.date ≤ d1.date` |
| 13 | Window operator `ω RANK()` | `COUNT{ … } < 3` within the same category |
